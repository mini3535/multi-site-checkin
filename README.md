# 多站点签到助手

部署在自己服务器上的自动签到服务，支持多个网站和账号，按计划运行并记录结果。

MIT 许可证：[LICENSE](LICENSE) · [第三方软件声明](THIRD_PARTY_NOTICES.md)

快速目录：[安装](#快速开始) · [添加签到](#添加签到) · [更新与维护](#更新与维护) · [卸载与清理](#卸载与清理)

## 快速开始

服务器需安装 Docker Engine、Docker Compose 插件 2.24.0+ 和 curl。通过 SSH 登录后运行：

    curl -fsSL https://raw.githubusercontent.com/mini3535/multi-site-checkin/main/install.sh -o autosign-install.sh
    sh autosign-install.sh /root/multi-site-checkin

按提示选择访问方式。**没有域名、或 80/443 已被其他网站占用时，可选「免自有域名 HTTPS」**：通过自己的 Tailscale 账号完成一次设备和 Funnel 授权，检查通过后直接打开生成的地址，使用助手密码登录并连接扩展，无需每台电脑配置 SSH。该方式依赖第三方服务可达性与账号权限。

已有宝塔、Nginx 等 HTTPS 反代时，选择「使用已有 HTTPS 反代」；安装器不会抢占端口。IP＋端口 HTTP 模式只适合可信网络，**不支持扩展自动连接**。安装结束会显示管理页面链接和初始密码；登录后可修改密码。具体步骤见[访问与安装说明](docs/OPERATIONS.md#安装与访问)。

## 添加签到

**首次准备：确认访问入口 → 安装扩展一次。日常添加：在网站登录 → 扩展识别并添加 → 验证签到 → 开启每日计划。**

1. 从安装器检查通过后显示的 HTTPS 地址登录助手。没有域名或 80/443 已占用时，先按顶部“使用指引 → 连接设置”配置免自有域名 HTTPS，或使用已有 HTTPS 反代。公网 HTTP 无法自动连接扩展。
2. 在自己电脑的 Chrome 中打开助手“网站目录”，展开“首次安装或更新浏览器扩展”，下载**与当前助手配套的扩展 ZIP** 并安装。添加其他网站无需重复安装。
3. 在另一个标签页登录目标网站，打开实际 HTTPS 签到页面。
4. 回助手点击“生成识别链接”并复制，切回目标网站标签页，打开扩展，粘贴链接，点击“识别网页并连接账号”。按 Chrome 提示授予权限。
5. 回到助手，点击“打开任务并验证”。系统会新建暂停任务，预填网页标题、登录状态和识别到的签到规则；未找到按钮时，先返回规则设置补充。
6. 点击“开始验证签到”，成功或显示今日已签到后，选择每天执行时间和时区，开启每日计划。

顶部“使用指引”始终提供连接设置、扩展安装、自动添加、验证与计划、更新与排障、卸载与清理六个入口。网站目录底部也有更新与卸载指引。目录和账号表单会根据当前访问地址显示连接提示；提示仅判断地址是否受支持，实际连接以扩展返回结果为准。四步任务向导仍是“选择网站 → 连接账号 → 验证签到 → 每天自动执行”。

**已有平台接口**：在网站目录选择 WorkBuddy 等平台，按其专用表单填写所需凭据，再验证和开启计划。
**手动配置网站**：粘贴 HTTPS 地址，进入表单后使用同一个扩展连接当前账号；Cookie、Token、账号密码和会话文件放在备用方式中。

浏览器流程支持可见内嵌签到页（iframe）。配套扩展 v1.3.1 可识别同源内嵌按钮；服务器仅在允许的域名内执行，多个按钮匹配时停止。ChatflowsAI 等内嵌页面使用正常控制台签到地址，不要保存带临时登录参数的内嵌链接。

一个网站账号对应一个任务。验证会真实执行一次签到。识别失败或网站提示不常见时，需要补充按钮或结果文字；更换账号、网址或规则后需重新验证。仅能在原生 iOS 或 Android App 中操作的签到暂不支持。

### 浏览器连接扩展

推荐从部署后的助手页面下载扩展，确保与服务器版本一致。扩展尚未上架 Chrome 网上应用店：解压 ZIP，在 `chrome://extensions` 开启“开发者模式”，点击“加载已解压的扩展程序”并选择解压文件夹。更新时用新包覆盖原文件夹，再在扩展管理页刷新。弹窗应有链接输入框和“识别网页并连接账号”按钮。

源码使用者也可下载仓库中的[当前扩展 ZIP](https://github.com/mini3535/multi-site-checkin/raw/refs/heads/main/signin-session-exporter.zip)。完整步骤见[扩展指南](browser-extension/README.md)。

目标网站必须使用 HTTPS；签到助手可使用自己的 HTTPS 域名、免自有域名的 HTTPS 入口，或仅在本机通过 `localhost` / `127.0.0.1` 访问（例如 SSH 隧道）。公网 HTTP 不支持浏览器连接，目录与表单会提供「查看连接设置」入口；其他访问方式也可随时从顶部“使用指引”查阅。连接链接五分钟过期且只能使用一次。详细说明见[扩展指南](browser-extension/README.md)。

## 支持范围

- 已适配平台：WorkBuddy、百度千帆、MiniMax Code、Qoder 国内版、Link AI、WPS 灵犀、Trae Work、Coze、华为码道。
- NodeSeek、hostloc 和其他网站：需自行确认签到页面并配置规则；尚未完成真实账号通用验证。
- LINUX DO 和豆包目前仅提供信息入口，不提供自动签到任务。
- 复杂登录、第三方登录或依赖 sessionStorage 的网站可能需要单独适配。

查看[平台能力与限制](PLATFORMS.md)。高级自定义规则见[源码示例](https://github.com/mini3535/multi-site-checkin/tree/main/examples)。

## 更新与维护

**日常操作：新版提醒 → 系统更新 → 立即更新 → 刷新使用新版。**

1. 登录助手，看到页面顶部的新版本提醒后，打开「系统更新」。系统每小时检查官方已发布镜像，也可点「检查更新」立即查询；GitHub 代码提交后需等待镜像发布完成才会提示。
2. 点击「立即更新」并确认。系统会下载并校验镜像、检查运行环境，暂停新操作并等待当前任务结束，备份数据库和原配置后重启。
3. 保持页面打开，等待状态恢复；重启期间可能短暂无法访问，无需重复点击更新或重新安装。看到「更新完成」后点「刷新使用新版」，或刷新网页并核对页脚构建版本。
4. 如果浏览器扩展版本有变化，从更新后的「网站目录」下载扩展 ZIP，覆盖电脑上的原扩展文件夹，再到 `chrome://extensions` 点刷新；只刷新旧文件夹不会下载新版。

**旧版没有「系统更新」入口，或提示更新服务尚未就绪：** 先在服务器终端执行一次[旧版首次启用或完整更新](docs/OPERATIONS.md#旧版首次启用或完整更新)，安装独立更新服务；只拉取助手镜像无法启用。完成后回原地址刷新网页，再点「系统更新 → 检查更新」。以后常规版本直接从网页更新。

网页更新保留访问方式、任务、密码和会话；新版启动失败时会尝试恢复旧镜像和更新前数据库。恢复成功后继续使用旧版；显示「需要人工恢复」时，按「系统更新」中的恢复指引处理，计划任务会保持暂停。备份在数据卷 `backups/web-updates/`，与原数据密钥一起保管。

网页安装只支持官方 `latest` 镜像。固定版本、自定义镜像、本地构建、更新服务自身或部署配置变化，仍按[维护文档](docs/OPERATIONS.md#更新已有服务器)在终端更新。源码部署先执行 `git pull --ff-only`。代码或镜像发布不会自行安装到服务器，需要你点击更新。

查看运行状态和日志：

    docker compose ps
    docker compose logs --tail=100 -f app

停止或启动：

    docker compose stop
    docker compose start

## 卸载与清理

**获取最新版卸载器 → 核对原安装目录 → 输入 DELETE → 检查残留。** 在服务器的交互终端操作，无需先升级镜像或重装。网页入口在“网站目录 → 卸载与清理”和顶部“使用指引 → 06 卸载与清理”。

确定不再使用时，先将需要的备份移到安装目录外，然后运行；将路径替换为自己的原安装目录：

```sh
cd /root/multi-site-checkin &&
  curl -fsSL https://raw.githubusercontent.com/mini3535/multi-site-checkin/main/install.sh -o /tmp/autosign-install.sh &&
  sh /tmp/autosign-install.sh "$PWD" --uninstall --purge
```

核对显示的卸载目录和删除范围，输入大写 `DELETE` 确认；其他输入取消。**不能添加 `< /dev/null`。** 此入口只更新卸载脚本并沿用原 Compose，不会启动或重装服务；旧版卸载后仍有原目录的，也可用来补充清理。原目录需仍有 `compose.yaml` 和 `setup.sh`，缺少时先核对原部署信息，不要重新安装空项目来卸载。

彻底卸载会删除本项目容器、网络、数据卷、任务、密码、会话、记录、证书、隧道身份、未共享的项目镜像和整个安装目录，包括源码、`.env` 及目录内备份。其他容器仍在使用的镜像会保留并列出。Docker 本身、共享构建缓存、目录外文件、外部反代、DNS、防火墙、Tailscale 账号设备记录和电脑 Chrome 扩展需按需自行收尾。

只想停用并保留任务、密码和会话时，使用上面的同一下载流程，**去掉最后的 `--purge`**；普通卸载保留数据卷、镜像、`.env` 和安装目录，之后在原目录运行 `sh setup.sh` 可恢复使用。

彻底卸载后运行 `cd ~` 离开已删除的路径，再按[检查卸载结果](docs/OPERATIONS.md#检查卸载结果)核对目录、容器、数据卷、网络和镜像。完整删除范围、旧版本清理与失败处理见[卸载服务](docs/OPERATIONS.md#卸载服务)。

## 数据与安全

任务和执行记录存于 SQLite 数据卷；账号凭据及浏览器会话使用安装目录中的密钥加密。请备份数据库和密钥，并限制备份文件访问。公网使用自己的 HTTPS 域名、已有 HTTPS 反代或免自有域名 HTTPS；IP＋端口模式使用 HTTP，仅适合可信网络，不能自动连接扩展。

## 开发与贡献

使用 Python 3.12+ 安装 `requirements.txt`，并准备 Playwright Chromium 后运行 Python 测试；Node.js 22+ 用于扩展测试。发布前检查：

    python -m unittest discover -s tests -v
    node --test browser-extension/popup.test.cjs
    python tools/package_extension.py --check

修改扩展后，运行 `python tools/package_extension.py` 更新唯一的 ZIP，再提交源码和 ZIP。CI 会先检查脚本和扩展，再构建、验证并发布双架构镜像。

镜像构建与发布状态见 [GitHub Actions](https://github.com/mini3535/multi-site-checkin/actions/workflows/container.yml)。代码推送成功不代表镜像已发布，也不会自动更新服务器。
