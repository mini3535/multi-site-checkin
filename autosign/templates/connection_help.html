01

让扩展连接你的助手

在服务器终端操作。
部署或更换访问入口时配置一次。

如果已通过 HTTPS 登录助手，可直接前往安装扩展。公网 IP＋端口的 HTTP 地址无法连接扩展，需要先选择下面的 HTTPS 入口。

没有域名，或 80/443 已被占用

选择“免自有域名 HTTPS”。在服务器的原安装目录运行下面的命令，不占用宿主机的 80/443 端口：

sh setup.sh --tunnel
  1. 打开终端显示的授权链接，在电脑浏览器中登录自己的 Tailscale 账号并批准设备。
  2. 如提示启用 HTTPS、Funnel 或批准设备，按链接完成授权。回到终端等待检查结束。
  3. 使用安装器检查通过后显示的 HTTPS 地址登录助手，保存这个地址。回到网站目录重新生成识别链接，再连接扩展。
此方式的适用条件与地址保存

此方式使用第三方 Tailscale Funnel，服务器需能访问该服务，账号策略需允许 Funnel。入口公开可访问，仍由助手密码保护。每台电脑无需配置 SSH 隧道。

设备身份保存在本项目数据卷；保留它才能在重启和升级后继续使用原设备地址。彻底卸载会删除本机身份数据，第三方账号中的设备记录需自行管理。

已有域名：宝塔、Nginx 等已在使用 80/443

在已有反向代理中新增签到域名并启用有效证书，上游指向同一服务器的 127.0.0.1:8080（改过助手端口时使用实际端口）。在原安装目录运行：

sh setup.sh --domain 你的签到域名 --external-proxy

此方式不启动额外的 Caddy。若反向代理在另一个容器中，需使用能访问助手的容器网络地址。

已有域名：80/443 空闲，可自动配置 HTTPS

域名已解析到服务器且端口开放后，在原安装目录运行：

sh setup.sh --domain 你的签到域名

已有入口切换方式会保留任务、密码和网站账号。请使用安装器检查通过后显示的新地址登录；仅把浏览器中的 HTTP 改为 HTTPS 不会配置证书。若脚本提示不支持上述参数，先按更新指引获取新版部署文件。本机通过 localhost / 127.0.0.1 访问时也可连接扩展。

03

从网页自动添加

在自己的电脑 Chrome 操作。
准备好助手和目标网站两个标签页。

  1. 目标网站标签页：正常登录自己的账号，打开实际签到页。目标网站需使用 HTTPS。
  2. 签到助手标签页：打开“网站目录”，点击“生成识别链接”，复制显示的链接。
  3. 切回目标网站标签页：打开签到助手扩展，粘贴链接，核对助手地址，点击“识别网页并连接账号”。按 Chrome 提示授予当前网站及助手站点权限。
  4. 回到签到助手标签页：看到结果后点击“打开任务并验证”。系统会创建一个暂停任务，预填网页名称、登录状态与识别到的签到规则。

识别链接是扩展的一次性连接码，5 分钟失效，不是扩展安装包或下载链接。过期后回目录重新生成。

两个连接入口的区别：网站目录里的“生成识别链接”会新增任务；具体网站表单里的“生成一次性连接链接”会连接当前表单，结果填回本页，需保存后继续验证。更新已有任务的登录状态，请在该任务的编辑页操作。

WorkBuddy 等已适配平台可直接选择目录中的专用账号表单，按字段提示操作。每个账号单独添加任务；仅能在原生手机 App 内操作的签到暂不支持。

04

验证并开启每日计划

在签到助手网页操作。
任务创建后先保持暂停。

  1. 核对签到页面和识别到的按钮。未找到按钮时，返回规则设置填写实际按钮文字或步骤。
  2. 点击“开始验证签到”。这会真实执行一次操作，请核对网站里的签到结果。
  3. 验证成功或显示“今日已签到”后，设置每天执行时间和时区，再开启每日计划。
  4. 回到“任务总览”查看下次执行时间和最近结果。服务器需保持运行；登录失效或遇验证码时，按“需要处理”提示重新登录、连接账号并验证。

自动识别提供配置线索，仍需核对验证。更换账号、网址或规则后需要重新验证；中途离开时，可在任务卡片点击“继续设置”接着完成。

05

更新与常见问题

更新助手在服务器终端操作。
更新扩展在电脑 Chrome 操作。

GitHub 更新不会自动更新服务器。镜像发布完成后，在原安装目录更新；普通更新保留任务、密码和账号会话，也沿用现有访问方式。

只更新助手镜像

在服务器终端进入原安装目录后运行：

sh setup.sh < /dev/null

更新完成后刷新网页，页脚“构建版本”可用于核对实际运行版本。固定使用旧镜像标签时，先修改原 .env 中的 AUTOSIGN_IMAGE。

旧脚本不支持新参数，或需要完整更新

先把必要备份放到安装目录外。将下面的目录替换为自己的原安装目录；自行修改过 Compose 时先保存修改。随后在服务器终端执行：

cd /root/multi-site-checkin &&
  if [ -f .env ]; then
    curl -fsSL https://raw.githubusercontent.com/mini3535/multi-site-checkin/main/install.sh -o /tmp/autosign-install.sh &&
    sh /tmp/autosign-install.sh "$PWD" < /dev/null
  else
    echo '未找到原 .env，请确认原安装目录，已停止更新。'
  fi

这会同步部署文件并更新镜像。原有访问方式保持不变；如要改成免自有域名 HTTPS，更新后再在原目录运行 sh setup.sh --tunnel。源码部署先执行 git pull --ff-only，本地构建则继续使用 --local 参数。

扩展连接失败、链接过期或只能下载文件
  1. 确认助手通过 HTTPS 或本机地址打开，目标网站使用 HTTPS 且已经登录。更换助手地址后重新生成链接。
  2. 链接 5 分钟过期，只能成功使用一次。回原页面生成新链接，切到目标网站标签页重新连接。
  3. 确认 Chrome 已授予当前网站与助手地址的权限。按本页安装步骤重新下载配套扩展，覆盖原文件夹后在扩展管理页刷新；只刷新旧文件夹不会升级。
  4. 仍失败时，在扩展弹窗展开“改用本机文件导出”，将会话文件上传到网站表单的备用入口。文件包含登录凭据，导入后删除不需要的副本；仅在可信连接中传输。
