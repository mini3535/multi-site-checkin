首次启用、特殊部署或自动恢复失败

旧版需要在服务器终端升级一次，装入网页更新服务。先备份数据和原 .env；把下方目录替换为自己的原安装目录。自行修改过 Compose 时先保存修改。

cd /root/multi-site-checkin &&
  if [ -f .env ]; then
    curl -fsSL https://raw.githubusercontent.com/mini3535/multi-site-checkin/main/install.sh -o /tmp/autosign-install.sh &&
    sh /tmp/autosign-install.sh "$PWD" < /dev/null
  else
    echo '未找到原 .env，请确认原安装目录，已停止更新。'
  fi

网页更新仅支持官方 latest 镜像，且只更新应用和随附扩展。自定义镜像、本地构建、固定标签，以及部署配置变化，仍在终端更新。独立更新服务持有 Docker 权限，仅接受本项目固定的更新操作，不开放网络端口。

自动恢复未完成时，先检查 docker compose logs --tail=100 updater、docker compose ps 和磁盘空间。排除问题后在原目录运行 docker compose exec -T updater python -m autosign.updater --recover，重试恢复旧版。数据备份位于数据卷的 backups/web-updates/，包含数据库和原 .env，请妥善保管。不要删除数据卷或重新生成密钥。
